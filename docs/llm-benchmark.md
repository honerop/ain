# Real LLM code benchmark (provider intentionally unconfigured)

This benchmark evaluates **programs generated by an LLM** rather than comparing
source file sizes. No OpenCode, API provider, or model is built in. Supply the
responses from any model yourself; a provider adapter can be added later.

The runner can:

- generate consistent prompts for Ain, Python, Rust, and TypeScript;
- compile produced Ain, Rust, and TypeScript files (Python runs directly);
- run each candidate on multiple cases **not included in the prompt**;
- report first-try successes, successes within an attempt budget, failures,
  compile time, candidate runtime, and provided token usage;
- save machine-readable JSON for later aggregation.

It cannot currently **invoke a model**. Thus it does **not** produce real
LLM-generation success or token results until actual model responses are
supplied. All token fields remain `null` if usage was not recorded by the model
provider. Do not label hand-written smoke-test code as LLM benchmark evidence.

## 1. Export prompts

From the repository root:

```sh
python3 tools/llm_bench.py --export-prompts /tmp/ain-llm-prompts
```

Prompts appear under `/tmp/ain-llm-prompts/<task>/<language>/prompt.txt`.
Use the same model, decoding parameters, attempt budget, and system-level
instructions across languages. The prompt contains a short Ain language guide,
but not the validation cases.

## 2. Provide the generated responses

For every task/language/attempt, save **the model's raw, complete source
code**, not Markdown, in a JSON file:

`responses/<task-id>/<language>/1.json` (and `2.json`, etc.)

Example `responses/sum-two/python/1.json`:

```json
{
  "source": "import sys\na, b = map(int, sys.stdin.read().split())\nprint(a + b)\n",
  "provider": null,
  "model": null,
  "usage": null,
  "generation_seconds": null
}
```

When the model API supplies reliable token counts, set
`usage.input_tokens` and `usage.output_tokens` to those actual integers.
The runner will not infer counts from bytes or treat missing counts as zero.
Keep the original LLM transcripts and model settings separately when running
a publishable experiment.

## 3. Evaluate actual outputs

**Security warning:** generated code and compilation can execute arbitrary OS
operations. The runner is **not** an OS sandbox. Only run unknown code inside
a genuine isolated VM/container with strict filesystem/network restrictions.
The explicit flag is an acknowledgement, not protection.

```sh
# Inside a disposable isolated environment with the needed compilers installed:
python3 tools/llm_bench.py \
  --responses-dir ./responses \
  --attempts 3 \
  --report ./results/llm-bench.json \
  --allow-unsafe-execution
```

For Ain, the runner invokes `ainc build FILE.ain -o PROGRAM`. Use
`--ainc /path/to/ainc` if it is not on `PATH`. Rust needs `rustc`;
TypeScript needs `tsc` and `node`. Python uses the Python interpreter
running the harness. Select a subset with `--languages ain,python`.

Missing response files are reported as `missing`, not as successful trials.
A generated program passes only if it compiles (where applicable), exits 0,
and emits exactly the expected stdout for **every** case. Execution timeouts,
runtime failures, and wrong outputs fail.

`results/llm-bench.json` contains per-attempt status, each case result,
compile diagnostics, source SHA-256, supplied model/usage fields, and summary
counts. Large stdout/stderr messages are truncated in reports.

## Interpretation

- **First-attempt success**: number of tasks passing on attempt #1.
- **Solved within budget**: number of tasks with *any* passing attempt.
  This is **not** unbiased statistical `pass@k`; no such claim is made.
- **Input/output tokens**: total supplied real provider usage for responses
  with both fields present; missing usage stays unknown.
- **Execution time**: wall time of short subprocesses; includes process startup
  and is not a reliable microbenchmark of algorithmic runtime.
- Test cases are excluded from prompts but remain in the public task
  manifest. Do not provide the benchmark file or a repository checkout to the
  model during evaluation. For rigorous research, put fresh secret cases in
  private task manifests, use multiple models and samples, and freeze prompts.

The six initial tasks are a **smoke-test-sized corpus**, not proof of a
language-wide advantage. The separate
[`token-benchmark.md`](token-benchmark.md) measures source tokens only.

## Development tests

```sh
python3 -m unittest discover -s tests -p 'test_llm_bench.py' -v
```

These tests use hand-written, trusted Python programs to exercise the
evaluation machinery. They **do not** generate an LLM performance score.
